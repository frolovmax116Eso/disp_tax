# ADMIN PANEL
# Админ-панель системы

Этот документ описывает функциональность админ-панели для администраторов платформы.

---

## Назначение

Админ-панель — это "камера наблюдения" за всей системой. Администратор видит все данные, но не вмешивается в работу диспетчеров.

---

## Доступ

### Whitelist админов

Админы определяются по Telegram ID в конфигурации:

```python
# .env
ADMIN_IDS=123456789,987654321
```

### Проверка доступа

```python
from src.config import settings

def is_admin(telegram_id: int) -> bool:
    """Проверка прав администратора."""
    return telegram_id in settings.admin_ids_list
```

### Middleware для проверки

```python
@dp.message_handler(commands=['admin', '/a'])
async def admin_command_handler(message: Message):
    if not is_admin(message.from_user.id):
        await message.answer("❌ Доступ запрещен")
        return
    # Обработка команды
```

## Функциональность

### 1. Просмотр всех диспетчеров

**Команда:** `/admin_dispatchers`

**Информация:**
- Telegram ID
- Имя и username
- Статус сессии (активна/неактивна)
- Количество заказов (всего/активных)
- Количество групп
- Последняя активность
- Дата регистрации

**Формат вывода:**
```
👤 Диспетчеры (всего: 5)

1. @username (ID: 123456789)
   Имя: Иван Иванов
   Сессия: ✅ Активна
   Заказов: 45 (активных: 3)
   Групп: 12
   Последняя активность: 2 часа назад

2. @username2 (ID: 987654321)
   ...
```

**Детали диспетчера:**
- При клике на диспетчера — детальная информация
- Список всех заказов
- Статистика по периодам

---

### 2. Просмотр всех заказов

**Команда:** `/admin_orders [фильтры]`

**Фильтры:**
- По диспетчеру: `/admin_orders dispatcher:123456789`
- По состоянию: `/admin_orders state:active`
- По дате: `/admin_orders date:2024-01-15`
- По VIP: `/admin_orders vip:true`

**Информация:**
- ID заказа
- Диспетчер
- Состояние
- Текст заказа (краткий)
- Количество ответов
- Назначенный водитель
- Дата создания/обновления

**Формат вывода:**
```
📋 Заказы (всего: 123)

1. Заказ #45
   Диспетчер: @username (ID: 123456789)
   Состояние: ✅ ACTIVE
   Ответов: 5
   Водитель: не назначен
   Создан: 2024-01-15 10:30:45

2. Заказ #46
   ...
```

**Детали заказа:**
- При клике — полная информация
- История состояний
- Все ответы водителей
- История назначений

---

### 3. Просмотр всех ответов

**Команда:** `/admin_responses [order_id]`

**Без order_id:** Все ответы всех заказов

**С order_id:** Ответы конкретного заказа

**Информация:**
- ID ответа
- Заказ
- Водитель (ID, имя, username)
- Группа
- Текст ответа
- Тип ответа ("я" или reply)
- Время ответа

**Формат вывода:**
```
💬 Ответы водителей (всего: 234)

1. Ответ #123
   Заказ: #45
   Водитель: @driver (ID: 111222333)
   Группа: "Такси Москва"
   Текст: "я"
   Тип: YA
   Время: 2024-01-15 10:35:12

2. Ответ #124
   ...
```

---

### 4. Просмотр всех назначений

**Команда:** `/admin_assignments [order_id]`

**Информация:**
- ID назначения
- Заказ
- Водитель
- Назначил (диспетчер)
- Причина (если смена)
- Активно ли назначение
- Время назначения

**Формат вывода:**
```
👥 Назначения (всего: 89)

1. Назначение #12
   Заказ: #45
   Водитель: @driver (ID: 111222333)

2. Назначение #13 (смена)
   Заказ: #45
   Водитель: @driver2 (ID: 444555666)
   Причина: "Первый водитель не ответил"
   ...
```

### 5. Просмотр логов и ошибок

**Команда:** `/admin_logs [level] [component]`

**Фильтры:**
- По уровню: `level:ERROR`
- По компоненту: `component:telethon_client`
- По времени: `time:last_hour`

**Уровни:**
- `INFO` — информационные сообщения
- `WARNING` — предупреждения
- `ERROR` — ошибки
- `CRITICAL` — критические ошибки

**Формат вывода:**
```
📊 Логи (ERROR, последний час)

1. 2024-01-15 10:30:45 - ERROR
   Компонент: telethon_client
   Сообщение: Failed to send message to group #789
   Контекст: {"order_id": 123, "group_id": 789}

2. 2024-01-15 10:25:12 - CRITICAL
   ...
```

**Детали лога:**
- При клике — полный контекст
- Stacktrace (если есть)
- Связанные логи

---

### 6. Статистика системы

**Команда:** `/admin_stats [period]`

**Периоды:**
- `today` — сегодня
- `week` — неделя
- `month` — месяц
- `all` — все время

**Информация:**
- Количество диспетчеров (всего/активных)
- Количество заказов (по состояниям)
- Количество ответов
- Количество назначений
- Активность за период
- Ошибки за период

**Формат вывода:**
```
📈 Статистика (сегодня)

👤 Диспетчеры:
   Всего: 5
   Активных: 4
   С активными заказами: 3

📋 Заказы:
   Всего: 45
   Активных: 12
   Назначенных: 8
   Закрытых: 20
   Отмененных: 5

💬 Ответы:
   Всего: 234
   Среднее на заказ: 5.2

👥 Назначения:
   Всего: 8
   Смен: 2

⚠️ Ошибки:
```

## Автоматические уведомления

### Получение всех ошибок

Админ автоматически получает все ошибки уровня ERROR и CRITICAL:

```python
async def send_error_to_admin(error: Exception, context: dict):
    """Отправка ошибки админу."""
    for admin_id in settings.admin_ids_list:
        await bot.send_message(
            admin_id,
            f"🚨 Ошибка: {error}\nКонтекст: {context}"
        )
```

**Формат уведомления:**
```
🚨 Ошибка в системе

Компонент: telethon_client
Тип: ConnectionError
Сообщение: Failed to connect to Telegram API

Контекст:
{
  "order_id": 123,
  "group_id": 789,
  "attempt": 3
}

Время: 2024-01-15 10:30:45
```

## Логирование действий админа

Все действия админа логируются в `AdminAccessLog`:

```python
async def log_admin_action(
    admin_id: int,
    action: str,
    details: dict | None = None
):
    """Логирование действия админа."""
    await save_admin_access_log(
        admin_id=admin_id,
        action=action,
        details=details
    )
```

**Типы действий:**
- `view_dispatchers` — просмотр диспетчеров
- `view_orders` — просмотр заказов
- `view_responses` — просмотр ответов
- `view_assignments` — просмотр назначений
- `view_logs` — просмотр логов
- `view_stats` — просмотр статистики

## Ограничения

### Read-only доступ

Админ **НЕ МОЖЕТ:**
- Изменять заказы
- Назначать водителей
- Редактировать настройки диспетчеров
- Удалять данные

Админ **МОЖЕТ:**
- Просматривать все данные
- Видеть логи и ошибки
- Получать статистику
- Мониторить систему

---

## Безопасность

### Проверка прав

- Все команды проверяют whitelist
- Неавторизованные пользователи блокируются
- Все действия логируются

### Защита данных

- Админ не видит пароли/токены
- Сессии диспетчеров не раскрываются
- Конфиденциальные данные скрыты

---

## Заключение

Админ-панель обеспечивает:
- Полную прозрачность системы
- Мониторинг всех процессов
- Отслеживание ошибок
- Анализ статистики
- Аудит действий

**Принципы:**
- Read-only доступ
- Полная видимость
- Автоматические уведомления
- Логирование всех действий
