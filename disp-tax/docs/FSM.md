# FSM (FINITE STATE MACHINE)
# Order Lifecycle

Этот документ описывает конечный автомат (FSM) для жизненного цикла заказа.

---

## Состояния заказа

### 1. DRAFT (черновик)
**Описание:** Заказ создан, но не готов к отправке.

**Действия:**
- ✅ Редактирование всех полей
- ✅ Удаление заказа
- ✅ Переход в PREVIEW

**Переходы:**
- `DRAFT → PREVIEW` — после нормализации текста

**Ограничения:**
- Не виден водителям
- Нельзя отправить

---

### 2. PREVIEW (предпросмотр)
**Описание:** Заказ нормализован и готов к просмотру.

**Действия:**
- ✅ Просмотр preview
- ✅ Редактирование (возврат в DRAFT)
- ✅ Подтверждение (переход в CONFIRMED)
- ✅ Удаление заказа

**Переходы:**
- `PREVIEW → DRAFT` — редактирование
- `PREVIEW → CONFIRMED` — подтверждение диспетчером

**Ограничения:**
- Не виден водителям
- Нельзя отправить без подтверждения

---

### 3. CONFIRMED (подтвержден)
**Описание:** Диспетчер подтвердил заказ, готов к отправке.

**Действия:**
- ✅ Отправка в группы (переход в SENDING)
- ❌ Редактирование (запрещено)
- ✅ Отмена (переход в CANCELLED)

**Переходы:**
- `CONFIRMED → SENDING` — начало отправки
- `CONFIRMED → CANCELLED` — отмена заказа

**Ограничения:**
- Нельзя вернуться к DRAFT/PREVIEW
- Нельзя редактировать без отправки

---

### 4. SENDING (отправка)
**Описание:** Заказ находится в процессе отправки в группы.

**Действия:**
- ✅ Продолжение отправки
- ✅ Отмена отправки (переход в CANCELLED)
- ✅ Завершение отправки (переход в ACTIVE)

**Переходы:**
- `SENDING → ACTIVE` — все сообщения отправлены
- `SENDING → CANCELLED` — отмена во время отправки

**Ограничения:**
- Нельзя редактировать во время отправки
- Применяется Anti-Ban логика

**Особенности:**
- Показывает прогресс отправки
- Уведомляет о FloodWait
- Может быть приостановлена

---

### 5. ACTIVE (активен)
**Описание:** Заказ отправлен во все выбранные группы, ожидает ответов.

**Действия:**
- ✅ Просмотр ответов водителей
- ✅ Назначение водителя (переход в ASSIGNED)
- ✅ Редактирование заказа (обновление всех сообщений)
- ✅ Отмена заказа (переход в CANCELLED)

**Переходы:**
- `ACTIVE → ASSIGNED` — назначен водитель
- `ACTIVE → CANCELLED` — отмена заказа
- `ACTIVE → ACTIVE` — редактирование (остается в ACTIVE)

**Ограничения:**
- Можно редактировать, но заказ остается активным
- Все изменения синхронизируются в группы

---

### 6. ASSIGNED (назначен)
**Описание:** Водитель назначен на заказ.

**Действия:**
- ✅ Просмотр назначения
- ✅ Смена водителя (остается в ASSIGNED)
- ✅ Закрытие заказа (переход в CLOSED)
- ✅ Отмена заказа (переход в CANCELLED)

**Переходы:**
- `ASSIGNED → CLOSED` — заказ выполнен
- `ASSIGNED → CANCELLED` — отмена заказа
- `ASSIGNED → ASSIGNED` — смена водителя

**Ограничения:**
- Новые ответы больше не принимаются
- Можно только сменить водителя или закрыть/отменить

---

### 7. CLOSED (закрыт) — КОНЕЧНОЕ
**Описание:** Заказ выполнен и закрыт.

**Действия:**
- ✅ Просмотр истории
- ❌ Любые изменения (запрещены)

**Переходы:**
- Нет (конечное состояние)

**Ограничения:**
- Нельзя изменить состояние
- История сохраняется неизменной

---

### 8. CANCELLED (отменен) — КОНЕЧНОЕ
**Описание:** Заказ отменен диспетчером.

**Действия:**
- ✅ Просмотр истории
- ❌ Любые изменения (запрещены)

**Переходы:**
- Нет (конечное состояние)

**Ограничения:**
- Нельзя изменить состояние
- История сохраняется неизменной

---

## Диаграмма переходов

```
     DRAFT
       ↓
   PREVIEW
    ↙  ↘
DRAFT  CONFIRMED
         ↓
      SENDING
       ↙  ↘
  CANCELLED  ACTIVE
              ↙  ↘
         CANCELLED  ASSIGNED
                      ↙  ↘
                 CANCELLED  CLOSED
```

---

## Правила переходов

### Разрешенные переходы

1. **DRAFT → PREVIEW**
   - Условие: текст нормализован
   - Действие: создание preview

2. **PREVIEW → DRAFT**
   - Условие: диспетчер редактирует
   - Действие: возврат к редактированию

3. **PREVIEW → CONFIRMED**
   - Условие: диспетчер подтвердил
   - Действие: фиксация заказа

4. **CONFIRMED → SENDING**
   - Условие: начало отправки
   - Действие: переход в процесс отправки

5. **SENDING → ACTIVE**
   - Условие: все сообщения отправлены
   - Действие: заказ активен, ожидает ответов

6. **SENDING → CANCELLED**
   - Условие: отмена во время отправки
   - Действие: остановка отправки, отмена заказа

7. **ACTIVE → ASSIGNED**
   - Условие: водитель назначен
   - Действие: фиксация назначения

8. **ACTIVE → CANCELLED**
   - Условие: диспетчер отменил
   - Действие: отмена заказа

9. **ACTIVE → ACTIVE**
   - Условие: редактирование заказа
   - Действие: обновление всех сообщений

10. **ASSIGNED → CLOSED**
    - Условие: заказ выполнен
    - Действие: закрытие заказа

11. **ASSIGNED → CANCELLED**
    - Условие: отмена после назначения
    - Действие: отмена заказа

12. **ASSIGNED → ASSIGNED**
    - Условие: смена водителя
    - Действие: новое назначение

13. **CONFIRMED → CANCELLED**
    - Условие: отмена до отправки
    - Действие: отмена заказа

### Запрещенные переходы

- Из CLOSED в любое состояние
- Из CANCELLED в любое состояние
- Из CONFIRMED в DRAFT/PREVIEW
- Из SENDING в ACTIVE без завершения отправки
- Из ASSIGNED в ACTIVE

## Валидация переходов

### Функция валидации

```python
def can_transition(current_state: OrderState, new_state: OrderState) -> bool:
    """Проверка возможности перехода между состояниями."""
    allowed_transitions = {
        OrderState.DRAFT: [OrderState.PREVIEW],
        OrderState.PREVIEW: [OrderState.DRAFT, OrderState.CONFIRMED],
        OrderState.CONFIRMED: [OrderState.SENDING, OrderState.CANCELLED],
        OrderState.SENDING: [OrderState.ACTIVE, OrderState.CANCELLED],
        OrderState.ACTIVE: [OrderState.ASSIGNED, OrderState.CANCELLED, OrderState.ACTIVE],
        OrderState.ASSIGNED: [OrderState.CLOSED, OrderState.CANCELLED, OrderState.ASSIGNED],
        OrderState.CLOSED: [],  # Конечное состояние
        OrderState.CANCELLED: [],  # Конечное состояние
    }
    return new_state in allowed_transitions.get(current_state, [])
```

## История состояний

Каждый переход сохраняется в `OrderHistory`:

```python
{
    "order_id": int,
    "old_state": OrderState | None,
    "new_state": OrderState,
    "changed_by": int,  # Telegram ID диспетчера
    "change_reason": str | None,
    "changes": dict,  # Детали изменений
    "created_at": datetime
}
```

## Особые случаи

### Редактирование активного заказа
- Заказ остается в состоянии ACTIVE
- Все сообщения в группах обновляются
- Создается запись в OrderHistory
- Ответы водителей сохраняются

### Отмена во время отправки
- Отправка останавливается
- Уже отправленные сообщения помечаются как отмененные
- Заказ переходит в CANCELLED
- Водители уведомляются об отмене

### Смена водителя
- Заказ остается в ASSIGNED
- Предыдущее назначение деактивируется
- Создается новое назначение
- История сохраняется

## Заключение

FSM обеспечивает:
- Четкий жизненный цикл заказа
- Контроль переходов между состояниями
- Неизменяемость истории
- Предсказуемое поведение системы
